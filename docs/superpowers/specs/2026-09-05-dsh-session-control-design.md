# dsh-session-control — дизайн

- Пакет: `@goodandready/dsh-session-control`
- Дата: 2026-09-05
- Ядро, под которое проектируем: DSH `0.1.2-rc.1`
- Статус: дизайн согласован, реализация не начата

## Задача

Дать управление сессиями в боковой панели: закреплять нужные диалоги, переносить
их между проектами, переименовывать по месту, находить старое и убирать лишнее
обратимо.

## Что уже умеет ядро

Проверено на живом production 2026-09-05, чтение без изменений.

| Возможность | Состояние |
|---|---|
| Проекты | Есть — «Рабочие папки» (workspaces): создание, переименование, удаление |
| Переименование сессии | Есть — пункт меню и `session/rename` |
| Полнотекстовый поиск по истории | Есть и работает — `session/search` возвращает сниппеты из тела диалогов |
| Порядок сессий и перенос между папками | API есть — `workspace/insertSessionBefore({workspaceId, sessionId, beforeSessionId?})`; вызов с чужим `workspaceId` и есть перенос. Интерфейса нет |
| Признак «сессия работает» | Есть в данных — `SessionSummary.running`. Не показывается |

Это мы не переписываем, а переиспользуем.

## Чего нет

1. **Закрепление.** Ни метода, ни поля, ни признака нигде в API и в UI.
2. **Перенос между папками в интерфейсе.** В меню сессии только три пункта:
   переименовать, ответвить, убрать в архив.
3. **Обзор без поиска.** Сессии видны только внутри раскрытой папки. Общего
   списка нет.
4. **Возврат из архива.** Архив односторонний, см. ниже.

### Архив ядра необратим

`WorkspaceRegistry.archiveSession` только добавляет:

```js
archiveSession(sessionId) {
  if (this.requireState().archivedSessionIds.includes(sessionId)) return;
  ...archivedSessionIds: [...state.archivedSessionIds, sessionId]
}
```

Метода «вернуть» в API нет. Плюс во всём модуле панели про архив есть ровно одна
строка — пункт меню `menu.archiveSession`; раздела с архивом не существует.
Сессия исчезает из интерфейса навсегда, хотя сама цела.

Поэтому наше «скрыть» строим отдельно и обратимо, а ядровый архив показываем
как отдельный раздел только на чтение.

## Ключевое ограничение: блок несущий

Тело боковой панели — единственный слот, и он не допускает второго регистранта.
Контракт `@deepseek-ai/dsh-client-ui-sidebar`:

```js
"sidebar.workspaces":    { kind: "single", scope: "root" },
"sidebar.settings":      { kind: "single", scope: "root" },
"sidebar.footer.action": { kind: "list",   scope: "root" },
```

`single` — значит «дополнить» нельзя, только заменить. А чтобы занять слот,
нужно освободить его, то есть выключить ядровый ряд `ui-workspace`.

Но тот же модуль отдаёт служебный сервис `uiWorkspace`, и он стоит в
**обязательном** `inject` у ядровых модулей:

```js
// dsh-client-ui-sidebar
const inject = ["slots", "layout", "uiWorkspace", "locale"]
// dsh-client-ui-conversation
const inject = ["slots", "sessions", "uiSession", "uiWorkspace", "locale", "settingsScope"]
```

Плюс он нужен `ui-agent-preset` и `ui-directory-picker-browse`. Просто выключить
`ui-workspace` нельзя: пропадёт `uiWorkspace`, и не поднимутся ни панель, ни
интерфейс беседы — экран будет пустой.

Значит, заменяя блок, мы обязаны отдать всё, что модуль отдавал.

## Пять обязательств замены

1. **`sidebar.workspaces`** — наш список. Ради этого всё.
2. **Сервис `uiWorkspace`** — около 120 строк, шесть методов
   (`connectWorkspace`, `startSession`, `archiveSession`, `pickDirectory`,
   `listDirectory`, `createDirectory`) плюс слежение за навигацией. Всё поверх
   публичных `workspace/*`, `session/*` и `remote.directoryPicker`.
3. **Дочерние слоты** `sidebar.workspaces.directoryFlow` и
   `conversation.hero.workspace.directoryFlow`, оба `single`/`root`. Без них
   отвалится выбор каталога при создании папки.
4. **`conversation.hero.workspace`** — выбор папки на пустом экране беседы.
5. **Корневой хук** `ctx.slots.provideRoot({ hooks: { workspaces: workspaces.list } })` —
   им пользуются чужие компоненты, воспроизвести как есть.

Объём при этом не «переписать модуль»: 125 КБ ядрового модуля — это React-вёрстка,
которую мы и так заменяем осознанно. Служебная часть небольшая и механическая.

## Устройство: две независимые половины

Плагин становится несущим, поэтому он обязан быть устроен так, чтобы его
поломка не гасила приложение. Один пакет, две половины, регистрируются
раздельно.

### Половина «сервис»

Только сервис `uiWorkspace`, объявления дочерних слотов и корневой хук. Без
React, без нашей логики, без настроек, без сети сверх ядровых вызовов. Её
единственная задача — никогда не падать. Пишется и проверяется первой.

Инъекции повторяют ядровые:

```js
inject = ["slots", "sessions", "workspaces", "locale", "remote", "remote.directoryPicker"]
```

### Половина «интерфейс»

Наш список: закрепление, перенос, скрытие, переименование по месту, поиск,
группировка. Регистрируется отдельно и целиком в `try/catch`.

**Смысл разделения:** если интерфейс сломается, слот `sidebar.workspaces`
останется пустым, но сервис жив — панель, настройки и беседа работают. Будь это
одна половина, любая опечатка в нашей вёрстке гасила бы весь DSH.

## Панель

Сверху вниз:

1. **Поиск** — то же поле, тот же `sessions.search(query, signal)` по содержимому.
2. **Закреплённые** — плоская группа, без папок, в порядке закрепления.
   Закрепление общее на всю панель, не внутри папки.
3. **Папки** — как сейчас: папка, внутри её сессии.
4. **Скрытые** — свёрнутый раздел, наше, возврат одним нажатием.
5. **Архив** — свёрнутый раздел, показываем только если непустой. Открыть
   можно, вернуть нельзя; подписать честно.

**Строка сессии:** заголовок, справа возраст, точка-индикатор при
`SessionSummary.running`, при наведении — `...`.

**Меню строки:** Закрепить / Открепить · Переименовать · Переместить в папку ▸ ·
Ответвить · Скрыть.

**Переименование:** двойной клик по заголовку, поле прямо в строке, без диалога.

**Настройки плагина:** карточка в «Настройки → Плагины → Настройки плагинов»
через слот `settings.plugin.item`, ключ карточки равен имени пространства
настроек. Своего раздела в боковом списке не заводим.

## Данные

Пространство настроек `dsh-session-control`, три поля:

| Поле | Тип | Смысл |
|---|---|---|
| `pinned` | `string[]` | sessionId закреплённых, порядок массива = порядок в панели |
| `hidden` | `string[]` | sessionId скрытых |
| `sections` | `object` | свёрнуто/развёрнуто для разделов «Скрытые» и «Архив» |

Настройки DSH серверные, поэтому закрепления переживают перезагрузку, смену
браузера и устройство. Своего хранилища не заводим.

Ссылка на исчезнувшую сессию — не ошибка: при отрисовке просто пропускаем
sessionId, которого нет в списке, и вычищаем при следующей записи.

## Потоки

Читаем те же источники, что ядровый модуль: `ctx.get("sessions")` и
`ctx.get("workspaces")` — их сторы дают список сессий, список папок и
`archivedSessionIds`. Свои поля читаем из настроек.

Порядок отрисовки: закреплённые вычитаем из папок, чтобы сессия не появлялась
дважды. Скрытые вычитаем отовсюду, кроме своего раздела.

Мутации идут прямо в ядровые методы: `session/rename`,
`workspace/insertSessionBefore`, `session/create`. Своих серверных маршрутов
плагин не добавляет — серверная половина нужна только чтобы объявить
пространство настроек.

## Обработка отказов

- Любая регистрация в слот — через `ctx.slots.inject(name, cb)`, чтобы имя,
  которого нет, было безвредным.
- Регистрация локали — однократная, с учётом того, что клиентское дерево
  применяется дважды за загрузку. Повторный `apply` не должен ни бросать, ни
  дублировать эффекты.
- Отказ любого ядрового вызова показываем в строке, а не проглатываем: молчащий
  `catch` уже дал нам два невидимых дефекта в других плагинах.
- Аварийный выход: `dsh plugin remove` возвращает ядровый ряд `ui-workspace` и
  штатную панель.

## Чего не делаем

- **Автоназвание диалогов.** Требует вызова модели, денег и отдельного
  обсуждения. Переименование по месту закрывает боль дешевле.
- **Отдельный режим «все диалоги по датам».** Папки уже группируют, поиск
  работает. Вводить, только если после обкатки окажется мало.
- **Множественное выделение, экспорт, теги, цвета.** Не просили.
- **Свой раздел в боковом списке настроек.** Карточка.

## Проверки

Тестового контура нет, функциональная проверка только на production после
merge проверенного `main` и явного «ок» на deploy.

Обязательный набор, каждый пункт с доказательством в issue:

1. Панель рисуется, папки и сессии на месте.
2. Закрепление: закрепить, перезагрузить страницу, открыть в другом браузере —
   осталось.
3. Перенос сессии в другую папку, порядок сохраняется после перезагрузки.
4. Скрыть и вернуть.
5. Переименование по двойному клику.
6. Поиск по содержимому находит старый диалог.
7. Создание папки с выбором каталога — проверяет обязательство №3.
8. Пустой экран беседы: выбор папки на месте — обязательство №4.
9. «Новая сессия» работает — обязательство №2.
10. Открытие беседы, отправка сообщения — интерфейс беседы жив.
11. Консоль при загрузке чистая, `Failed to load plugins` нет.

Пункты 7–10 — не формальность: это ровно то, что ломается при неполной замене.

## Порядок работ

1. Gitea-репозиторий, каркас, `cordis.patch.yml`, обезличенность с первого
   коммита.
2. Половина «сервис» + проверка, что панель и беседа живы при выключенном
   ядровом ряде и пустом слоте.
3. Половина «интерфейс»: список, папки, поиск.
4. Закрепление.
5. Перенос между папками.
6. Скрытие и раздел архива.
7. Переименование по месту.
8. Карточка настроек, README, документация.
9. Production-проверка по списку выше.

Доставка на прод до публикации: тарбол собирается из смерженного проверенного
`main` и кладётся в `~/.cache/dsh-artifacts/`. Ссылка в рабочий каталог DEV
недопустима ни на каком этапе. После публикации профиль переводится на обычную
версию из registry.
